## Lifecycle

The pilot gateway owns one scheduled observer while it holds the consumer lease. An immediate cycle is followed by a two-minute delay after each cycle. Active reads settle before shutdown closes their database. A paused pilot starts no new SLS request or projection. A history response received during pause is retained, and the next diagnostic sample remains due. The observer and CLI share a fixed poll implementation.

## Durable projection

A genuine inbound private message from the bound tenant, operator and chat establishes the notice destination. The observer retains a card UUID per incident milestone. The pilot retains one machine matter per incident without changing the owner's selection. Transport commits the delivery and card identity together. A repeated projection after a crash reuses the existing delivery. The observer records projection only after the transport commit. Projection means accepted by the local outbox. Feishu delivery uses its existing retries and message confirmation.

The current incident state determines the next notice. Pending milestones superseded before projection are coalesced. A subsequent change from resolved to needs attention gets a separate card on the same matter. An accepted inactive boundary between firings lets a new incident start after an earlier handoff exhausted its observation budget. A machine matter remains explicitly addressable, and unattended opening does not affect the choices for unrelated unanchored chat.

## Execution boundary

Only the enrolled owner's ordinary message can enter the existing admission/dispatch path. A reply to a confirmed incident card carries the card's bounded historical aggregate as reference. Direct requests and explicit switches use existing matter semantics. Events can neither launch a native task nor invoke the refund Job, submit refunds or change production state.
