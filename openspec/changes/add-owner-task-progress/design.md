# Design

Admission owns task identity and scheduling records; native owners own live progress; sealed native journals and verifier observations own historical outcomes; transport owns cards, message identity and delivery. Reuse the execution UUID. The enrolled private owner must also retain the existing maintenance approval role.

List ten tasks per page, with granted active/unknown tasks first, then unstarted work, then recent ended/withdrawn work. Disclose pagination and observation time. Selection is owner/chat/current canonical resource scoped in SQLite. Detail requires an exact UUID; invalid, foreign or unknown selectors cannot fall through to native work. Use the original user request only as a bounded escaped title.

Add an authenticated read-only owner-channel progress operation. Bridge exposes only activity category, native identity, current-round start/last-event timestamps and non-sensitive prompt tokens/expiry. It must not call State.pending, native snapshot/apply, model/tool APIs or control dispatch. Repair responses bind the current attempt and reject a transition race. Missing/unreachable owners show unverified liveness, not automatic interruption or completion. Sealed detail checks use the existing evidence reader and read-only journal timing; legacy missing timing remains unknown. Execution completion and verification outcome remain separate.

Detail cards carry an opaque presentation UUID. Transport persists redacted presentation and confirmed platform message identity; refresh callbacks must match authenticated app/tenant/operator/private chat, confirmed card message, presentation and owned execution. Refresh reuses the existing card through durable ordered patch deliveries. Uncertain sends/patches retry retained identity; they never create replacement cards after an uncertain patch or execute tasks. Duplicate query/callback receipts commit with their output. Persistent answer failure cannot poison synchronization/closure. Callback processing schedules bounded read work and returns promptly without model/network waits.

Card refresh is read-only. Approval uses the existing current-native-prompt decision path. A detail message is associated with its original task so quoting it for `/steer` or `/stop` cannot select a different running task. Stale terminal cards retain history and cannot control a new task. Queue withdrawal and inspected recovery remain under their existing authorization boundaries.

No continuous notifications or raw tool arguments/transcripts are added. Existing native prompts and final deliveries remain the actionable notifications. Older sealed journals are not migrated. New transport card facts remain in closed-state snapshots and archived pilot transport SQLite; reverse conversion preserves callback/query deduplication and task-message associations. The legacy runtime does not gain this P1-only view.
