The owner-private gateway derives explicit new-topic intent from a leading
phrase. It uses the rest of the message as the first request. An explicit
fresh start takes precedence over an ordinary quote or PR binding without
changing that existing binding. Topic identity remains scoped to the same
enrolled owner and canonical project. A new topic gets one conversation and
a readable title, including when an older topic has the same title.

An unquoted direct read or review request naming one canonical, unbound GitHub
PR can atomically start and bind that matter. The caller supplies a canonical
PR URL or an exact owner/repository plus PR number. Incidental links, ambiguous
addresses, and business write requests use existing routing or a held choice.
An additive request with a distinct subject may be offered the current matter
and a fresh matter. No classifier or new executor is required.

Fresh conversation creation, request admission, receipt provenance, focus and
any new PR binding share the admission transaction. Held messages reuse the
confirmed-card identity and original origin. Selecting a fresh topic processes
that same stored input. Selecting an existing target from a new-topic choice
routes only that message. Existing active-task controls, scoped permissions,
project routing refusals and verified quote continuations keep their authority.
