# Design

## Boundaries and observable behavior

Browser Use is the policy authority. The native observer owns only an immutable report that a particular tool item returned a saved-denial code for a canonical HTTP(S) origin. It accepts the exact node_repl/js browser metadata shape; model text, tool error prose and arbitrary MCP servers cannot create this observation. Strip paths/query/fragments, reject credentials/invalid origins and expose no raw arguments/content. Unsupported tool/error shapes keep existing behavior.

Add an optional native journal table scoped to native task/generation/item. Repeated identical events do not create another observation; old sealed journals without the table remain readable and unchanged. Existing authenticated progress IPC and checked sealed projections expose at most ten recent observations. A historical observation does not establish present policy, a failed business objective or absence of external side effects. Keep native completion, tool observation and delivery evidence distinct.

Owner-private task detail/listing shows the observation and local remediation. After source settlement, transport atomically records one notice receipt and its rich-post outbox entry under an execution-bound identity; delivery retry/restart cannot launch work or repeat notices. Keep native final answers and source bytes intact. No approval-like button is shown without a real provider authorization request.

## Explicit continuation

`/browser-retry <execution> local-change-confirmed` is a fresh owner attestation that settings were handled locally and a request to check and continue remaining work. The exact suffix prevents a pasted ID or verbal allow from becoming this instruction. It does not assert that the setting is effective.

Only enrolled private maintenance-owner messages qualify. Source must be an owned, completed ordinary task with verified sealed denial observations, no unknown execution protection, unchanged latest conversation/thread and no conflicting resource work. Exclude verification/repair sources. Admission transaction rechecks source checkpoint/conversation/guard and atomically consumes the source continuation identity with one fresh ordinary request. Different or duplicate message IDs return the existing request after uncertain receipt; they do not replay it. Source evidence is rechecked immediately before executor startup.

The new turn resumes the same native conversation under normal policy, verifies site access using the supported Browser Use path, inspects earlier effects, and continues only unfinished authorized work. A renewed denial remains blocked. It never invokes Guardian authorization, copies a native allow rule, changes browser settings or guarantees a send. New task/parent are linked in task views; original status remains unchanged. No model/verifier is called by views or guidance.

## Compatibility and policy authority

Journal observations are optional and read-only for old evidence. Admission continuation records remain in the captured handoff DB; preserve them during compatible backup/archive/rollback and do not downgrade an active consumer that cannot interpret them. Closed inventories retain original native policy separately. Browser settings remain external platform authority and are not reconstructed from task audit records.

The installed documented browser capabilities expose viewport and organization controls, not an origin-policy mutation API. ChatGPT plugin permission tools do not manage Chrome/code plugins. Current official remediation is desktop Settings > Computer Use > browser Manage; a managed policy may need its administrator. API availability changes require a separately reviewed adapter, not invented methods or direct private-store edits.
