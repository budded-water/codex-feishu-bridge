# 常见问题

先区分三种状态：消息被接收、Codex 工作完成、最终答案投递成功。表情 / 进程在线 / 通过 doctor 都不能代替完整任务验收。

## 安装与启动

| 现象 | 检查与处理 |
| --- | --- |
| clone 后只有 README，没有 package.json | 当前实现尚未合并 main；按 [安装说明](installation.md) 下载 docs/initial-architecture 分支 |
| Node SQLite、env-file 或执行时报错 | 用 Node.js 24 或更高版本，核对终端 / 后台实际 Node 路径；更新后 npm ci、check |
| 提示 Codex protocol requires 某版本 | 对照 [协议版本](../src/codex/generated/version.ts) 和 codex --version；安装兼容版本或维护协议升级，不跳过校验 |
| doctor 提示 ID / 项目 / 字段非法 | 模板不是即用配置；替换占位 ID 和目录，不用 `~`、相对项目路径、通配符或额外字段 |
| start 找不到 dist/index.js | 先 npm run build，或执行包含构建的 npm run check |
| service 找不到 codex，但终端正常 | 核对 PATH、codexExecutable 完整路径、工作目录、运行账号；重新生成本机 plist |
| 第二个进程无法获取锁 | 同一状态目录只能有一个进程；正常停止已有前台 / 后台实例，不删除活进程的锁 |
| 两台电脑都连同一个机器人，消息归属不稳定 | 一应用对应一个独立 bridge 部署；不同主机使用独立应用 / 状态，SDK 不按项目分发事件 |

## 飞书入口

| 现象 | 检查与处理 |
| --- | --- |
| 保存 SDK 长连接设置提示未连接 | 保持 npm run identify 在线，再配置事件；它只需 .env，无需 JSON 已填完 |
| identify 没有返回 ID | 私聊发送终端打印的完整 pair 挑战；超过 15 分钟重新生成；确认发布、事件和可用范围 |
| 机器人没有回应 | 保持主机唤醒和进程运行；核对凭据、订阅 im.message.receive_v1、发布和可用范围、JSON 准入 |
| 群里不回复但私聊正常 | enableGroups=true、正确群 @ 权限、机器人已入群，并通过选择器真实 @ 此机器人；命令也要 @ |
| 同事被忽略 | 核对 allowedTenant / accessMode / allowedUsers 和应用可用范围；IDs 属于此应用 |
| 改 .env 后仍用另一个应用 | 检查已经设置的同名环境变量 / 服务环境；正常重启；切换应用要重新核对用户和聊天 IDs |
| 改图标后飞书还是旧头像 | 检查头像是否随新版本发布并获批，确认改的是该应用；线上已更新后再刷新客户端 |

## 上下文、图片和显示

| 现象 | 检查与处理 |
| --- | --- |
| 说“上面的讨论”却读不到 | 自动前文默认关闭；按同意的范围开启配置与后台权限，或明确引用 / 粘贴相关内容 |
| 前文 API 报 230027 | 群 @ 接收权限不够；检查 message-read 与 im:message.group_msg 发布授权；本地开关不能授予平台权限 |
| 设置 50 但读到更少 | 只有一页，过滤机器人、触发消息、未来 / 超时 / 删除记录后可能更少；不继续分页补齐 |
| 给它发图片没有反应 | 当前触发器只收文本；先发图片，再发带 @ 的文本任务，或引用图片；开启图片参考与所需读取权限 |
| 图片未读 / 超限 | 核对 0–8 图片尝试数、支持格式、资源权限和字节限制；附件、卡片不展开，失败时不会猜内容 |
| 长答案有少量格式问题 | 使用富文本 post；极长单行会按 Unicode 硬拆分，跨段复杂行内格式可能不完整；保留完整任务结果并报告复现 |
| 没有收到表情 | 反应写权限或网络可能失败；会退回确认消息，答案投递独立；清理重试可能延迟 |

## 执行、审批与恢复

| 现象 | 检查与处理 |
| --- | --- |
| 想做代码工作却只讨论 | 先 /project alias；当前不会自然语言自动选项目 |
| 普通补充变成了另一个任务 | 忙碌时普通消息排队；用 /补充 内容 修改当前任务 |
| /new 被拒绝 | 当前会话尚有运行 / 排队任务；等待，或停止并清队列后再新建 |
| /stop 后还有后续工作 | stop 保留队列，另用 /clear；已有文件和外部动作不会自动回滚 |
| 任务一直等待 | 查看 /status 的阶段、耗时、事件年龄及待回复请求；本机进程已连接不证明模型连接正常；阶段提示最多一次 |
| 没出现审批或同事不能批准 | 审批依赖本机 Codex 策略；只有 designated approvalUsers 在 approvalChat 可决定，单个提问只由原提交者回答 |
| 本人发消息功能不可用 | bridge 普通回复是机器人；CLI --as user 需要有效 OAuth、消息 scope 和会话访问权，检查 auth status --json --verify |
| 开 PR / 搜索 / 文档读取不可用 | 核对本机对应工具、认证与资源权限；这些不是 bridge 内置账号能力 |
| 重启后任务没有继续 | 设计为不自动重跑不确定任务；先核对真实改动，再明确发新任务 |
| 结果发送失败 / 重复 | 持久化 outbox 会重试，不重跑 Codex；跨平台去重窗口的长故障仍可能重复 |

## 报告问题需要什么？

提供使用方式（个人 / 团队）、操作系统、Node 和 Codex 版本、脱敏配置、具体命令 / 复现步骤及 `/status` 的阶段。说明是安装、SDK 连接、模型执行还是答案投递失败。不要公开 `.env`、用户 token、真实聊天内容、状态数据库或带个人路径的日志；必要时先脱敏再分享。

历史验收记录只代表已有部署的观察，新部署还需要自己的测试；见 [真实验收记录](live-acceptance.md)。
