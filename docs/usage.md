# 使用说明：把工作交给 Codex 分身

这份说明给机器人使用者。你无需安装 Node、Codex 或飞书 CLI；需要应用部署者已把机器人发布给你，并把相关项目登记在运行电脑上。

工作在**部署者的本机环境**中执行。你登录飞书的身份用于准入和会话归属，不会把你自己的 GitHub、文件或飞书 OAuth 自动带到这台电脑。

## 私聊与群聊

私聊机器人，直接发送文本。群聊里每个任务和控制命令都需要真实 `@机器人`；通过飞书成员选择器选择它，输入同名字符串不能替代 @mention。以下 `@工作分身` 是示意名称，替换为部署者的实际机器人。

```text
@工作分身 /status
@工作分身 关于上面的讨论，你有什么建议？
```

普通群消息、@所有人、@别的机器人和机器人发送的消息不触发任务。仅发一个 @、图片、语音或文件也不启动任务。

## 讨论与项目执行

默认是讨论模式，回答本次问题。已有前文 / 图片权限时可讨论群内提供的资料；读不到资料会说明。直接说明项目和需求即可，Codex 能确定时会进入已登记项目，不清楚时会问一个简短问题。也可用 `web：具体需求` 这样的已登记别名前缀明确发起新任务，跳过模型分类；这是可选的明确选择，不会沿用旧的待澄清请求。也可手动指定：

```text
@工作分身 /project web
@工作分身 阅读项目规则，检查登录接口为什么返回 401，先给出原因和修复方案。
```

`web` 必须是部署者登记的别名；`/project` 不接受聊天里传入的任意路径。发送 `/project` 可查看已登记别名。Codex 也会收到别名清单与当前选择，但清单不会自动选择项目或授予执行权限。选择后，后续普通消息会在此项目继续执行；用 `/chat` 返回讨论。自动选择只允许登记目录，并根据当前用户的请求判断；群内他人的话不会替你切换项目。

查询业务数据时说明产品或项目名称，让 Codex 核对项目规则、数据结构和真实数据源，再使用本机已授权的 CLI 或工具。项目不明时机器人会澄清；数据源不明时先补充项目上下文，不能因为某个分析工具可用就假定产品使用它。请说明统计时间范围、活跃定义和测试账号排除规则；项目未登记时需要部署者添加配置。

每位同事在每个聊天下有自己的会话和选择；你的 `/project` 不会替别人切换项目。不过所有人对同一目录的工作会串行等待。

## 给出可执行的工作需求

| 任务 | 可以这样说 | 依赖 |
| --- | --- | --- |
| 资料分析 | “根据这段资料，对比三个方案，注明已验证事实与推断。” | 所需资料已提供或本机 Codex 有搜索 / 读取工具 |
| 修 Bug | “订单提交偶发重复，定位原因、修复并运行相关检查。” | 已选项目、可重现信息、本机执行权限 |
| 做功能 | “给设置页增加通知开关，遵循项目规则，完成实现、验证并开 PR。” | 已选项目、需求和验收标准、GitHub 工具身份 |
| Review 本地变更 | “Review 当前分支相对主分支的完整 diff，重点检查回归与测试。” | 已选项目、明确比较基线 |
| Review PR | “Review 这个 PR 链接，指出能定位到代码的具体问题。” | PR 可访问，本机有相关工具 / 授权 |
| 飞书文档工作 | “读取这份有权限的需求文档，对照代码找遗漏。” | 本机另配飞书文档工具及资源授权 |

这些是 Codex 工作任务，不是 bridge 内置的固定功能按钮。只有配置了相关工具和身份、项目规则允许的动作才有执行条件。“开 PR”也不表示它可以自动合并或发布。部署者应说明自己委托同事提交的工作范围。

## 收到表情后意味着什么？

收到普通任务时，机器人尝试在原消息加 `OnIt` 表情，代表已收到；失败时退回一句确认。排队有说明；等待期间不会定时刷状态；需要审批或回答时才提示，最终答案单独回复。完成、失败或取消后清理自己的表情；网络故障可能延迟反馈和清理。

表情不是持续的在线指示灯，也不是已完成证明。`/status` 显示本机 Codex 进程是否连接、当前阶段、耗时和最近的 Codex 事件时间；进程连接不保证模型网络健康。bridge 不会因长等待自动重跑你的请求。

## 命令表

群里以下每条都要先 @机器人；私聊不需要。

| 命令 | 行为 |
| --- | --- |
| `/help` | 查看帮助 |
| `/project alias` | 选择已登记项目，进入执行模式 |
| `/chat` | 返回普通讨论 |
| `/status` | 查看正在做什么、排队数量和待确认请求；`/status 详情` 展示技术诊断 |
| `/new` | 当前会话没有运行 / 排队任务时新建会话，不删除旧历史 |
| `/补充 内容` | 给当前选中的运行任务补充要求；不是给下一个任务 |
| `/stop` | 请求停止自己的当前运行任务，排队任务保留 |
| `/通知 @成员 内容` | 在当前群回复原提问并发送真实成员 @；通过成员选择器选人，一次最多 20 人，不创建或指派任务 |
| `/clear` | 取消自己的当前会话排队任务，运行任务不受影响 |
| `/批准 编号` | 指定审批人在指定聊天授权该请求 |
| `/拒绝 编号` | 指定审批人拒绝审批；原提交者可拒绝自己的提问 |
| `/回答 编号 内容` | 原提交者回答单个非敏感问题 |

`/补充` 和 `/回答` 的正文保留换行与代码缩进。普通消息在忙碌时会排队；想修正正在做的事情使用 `/补充`。想停止并清空后续工作，分别使用 `/stop` 和 `/clear`，并检查已经发生的文件 / 外部操作。

切换项目不会把已经排队的工作移到新目录，也不能用它控制别人的任务。原会话仍有工作时 `/new` 不会隐藏或丢弃审批。

## 审批在哪里处理？

命令 / 文件请求可以路由到部署者的指定私聊，提交者会收到等待说明；审批先说明项目、需求和用途，再完整展示本次动作与核对命令。原提问元数据可用时显示已核实的提交者和原消息链接；姓名读取失败会说明，私聊审批不 @ 不在该聊天的提交者。指定管理员在该聊天回复 `/批准 编号` 或 `/拒绝 编号`。显示按本机时区计算的实际截止时间；过期或已经处理的请求不会从待发送队列里再发出来，已在途的网络请求无法撤回。一般配置 300 秒超时，实际值由部署者设置；过期后拒绝，旧编号不能批准新任务。

单个非敏感问题仍由原提交者在原聊天用 `/回答 编号 内容` 回答，不必输入内部问题 ID；旧的匹配问题 ID 格式仍兼容。敏感问题、一个 RPC 中多个问题、扩展权限交互等暂不支持，会拒绝并提示到本机处理。不支持交互的详细原因留在 /status 和本机日志；最终答复说明影响和下一步，不额外插入技术提示。

审批仅在 Codex 的本机策略提出请求时出现；不能从“没有审批消息”推断没有做任何修改。

## 给它看群里图片或前文

先发送资料，再用一条文本 @机器人提问；也可引用要讨论的消息，包括 Bot 的原回复；引用会优先传给 Codex，即使同时开启自动前文。成员提及显示消息提供的姓名，身份信息不足时会明确标为未知，不会猜人。自动历史和图片下载默认关闭，需要部署者同意并配置。开启后只取触发前的有限上下文，机器人入群不会自动拿到全部历史、置顶文档和会议纪要。

消息写着 `[图片]` 不意味着图片已读到；bridge 会另行下载获准资源并作为真实图片输入，失败则明确未读。直接粘贴链接也不等于内容已展开。

## 等不到回复或任务中断

检查真实 @、应用可用范围和 `/status`。读不到前文时引用或粘贴内容；电脑休眠 / 断网需要部署者处理。进程退出或重启后，未确认完成的任务不自动重跑；重试之前检查已经发生的改动，避免重复执行。具体排查见 [常见问题](troubleshooting.md)。

## 更自然地补充、停止和通知

同一聊天下只有一个你正在运行的任务时，可以说“补充：只看最近一周”“只看最近一周”“先别修改”，它们会补充到当前任务；新任务仍排队。存在多个任务或引用无法关联时，会请你引用自己的原提问，不猜任务。执行阶段未引用任务、也未明确说“补充”或给出禁止修改等限制时，明确提到另一个已登记项目的读取需求按新任务处理。引用绑定、明确补充和分类中的限制会传给当前任务，不根据内部讨论工作区猜项目。也可引用 Bot 对该任务的回复；关联由 SQLite 记录并按租户、用户和聊天校验，引用其他人的任务不会替你控制它。

“先停一下”“停一下”“别继续了”停止绑定的当前任务，并清理该会话后面的排队请求；“停止当前任务”“取消当前任务”及 `/stop` 保留后续队列。已有操作不会自动撤回。任务尚未执行时的文字补充会加入首次输入；开始请求尚未确认时不会假装补充已接收，可以先停止再重新说明。停止未确认时明确要求核对本机结果，后续排队任务取消，不自动重跑。

群里可发送 `@Bot /通知 @成员 通知内容`，或者 `@Bot 请通知 @成员 通知内容`。成员必须是本条消息通过飞书选择器真实 @ 的目标，不根据显示名猜账号，不通知所有人，不跨聊天发送，私聊不通知第三人。发送真实 @ 不证明对方已读；分工建议、成员通知、创建任务和实际指派是不同动作。重复事件不会重复发送新的通知；投递失败按固定 UUID 重试，仍受平台去重窗口限制。

结果直接回复实际发起任务的消息，项目与内部任务编号不再默认附在答案末尾。引用消息被撤回或删除时，收到明确错误后才退回原聊天发送；网络结果不确定时继续重试原回复方式，不换地方重复发。消息过长及已获准用户的不支持格式会给出处理提示，而不是静默忽略。普通等待仍不定时刷消息，重启后的恢复说明按提交者/聊天汇总。

同一项目的执行结果未确认时，此前已进入分类流程的请求也会在交接时停止；先核对本机结果，再发起新请求，不自动重跑。简化问题回答只移除编号后的一个分隔符，保留内容的换行和缩进。
