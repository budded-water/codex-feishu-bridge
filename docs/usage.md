# 使用说明：把工作交给 Codex 分身

已配置 P1 验证 profile 的本人私聊还可使用 `/verify profile 任务内容` 和 `/verification 完整任务编号`；选择该 profile 会授权其登记的验证命令。原生任务完成后才进行验证，结果不等于独立 review 或发布授权，见 [项目验证](project-verification.md)。实际部署和验收范围另见 [验收记录](live-acceptance.md)。

若 profile 另有受信任的 repair 策略，可用 `/verify-repair profile 任务内容` 显式允许一次修复续接。仅符合登记条件的功能断言失败会触发，最多两轮 Codex 和两次完整验证；`/stop` 停止整个任务。普通 `/verify` 仍为单轮。见 [有界修复](bounded-repair.md)；部署和实际飞书验收分别记录。

## 交付等待（P1 网关）

在登记的本人审批私聊中，用已完成的普通任务编号保存一份待验收证据。引用须
是一个最长 240 字符的标识，以英文字母或数字开头，其余可用英文字母、数字和
`:./_@+=?&%#-`。例如含哈希的 iOS 候选标识或含版本参数的 Web 预览 URL。
编号来自 `/task`，同一原任务只登记一份证据。

```text
/delivery-wait 任务编号 ios:release-41@sha256:abc123
/delivery 任务编号
```

如果使用 `/verify` 得到通过的 Web 报告，发送 `/delivery-wait 验证任务编号`。
机器人从原记录生成引用，回复显示源码提交，并给出可复制的 `/verification` 查询。
确认和 Worker 启动前会核对提交、工作区、验证规则及 JSON/HTML 报告。
确认前证据失效时，保留等待记录并显示原因。入队后证据变化时，续接在启动前结束。

确认并继续时，从原回复复制同一编号和证据引用。用纯文本发送，第二行写明本轮
希望处理的任务。下面的示例标识需替换成实际登记的 ASCII 引用。

```text
/delivery-confirm 任务编号 ios:release-41@sha256:abc123
只读取并核对该候选的验收报告。
```

查询和登记只保存或读取记录。确认将本人的下一轮任务关联到原会话，可重启后查询，
每份证据至多续接一次。项目工具继续管理自己的证据和实际状态，续接沿用普通 Codex
任务的权限与审批。构建、验收和发布仍以各自工具
的实际回执为准。

## 逐任务进度（P1 网关）

用 `/tasks` 查看当前任务概览：执行、未开始和待检查数量分开显示，附最近三条历史记录。`/tasks 1` 查看完整记录，每页 10 个，`/tasks 2` 继续翻页。历史记录包含已经结束的验收请求，数量不代表当前待办。

用 `/task 完整任务编号` 查看普通／验证／修复任务详情，也支持从机器人回复复制后形成的纯文字富文本查询。详情卡片可点击“刷新进度”；展示真实阶段、当前轮次耗时、最近事件和需要本人处理的事项，不估算百分比或调用模型总结。引用该卡片发送 `/steer 内容`、`/stop` 会绑定原任务；历史卡片不能控制新任务。审批仍使用原审批卡片或其英文命令。查看不重跑、不解除保护，详见 [任务进度与边界](task-progress.md)。

## 验证线索（P1 网关）

在已登记本人的私聊中，本人兼审批人可发送 `/findings`，汇总当前工作区中自己最近 100 条验证任务：每个 profile 取最新登记任务，最多显示 10 个非通过 profile。同一 profile 的新任务会取代旧线索；最新记录为通过时不列出，但这不证明旧问题已修复，空列表也不代表项目没有问题。

每项区分执行中、未确认、证据无法核实和历史验证观测，并提供可复制的 `/verification 完整任务编号`。封存证据可核实时另行显示 profile、规则、源码和报告的当前适用性；这些仍是历史观测，没有重新检查环境。失败可能来自产品、基础设施或人工复核要求，不能统一当作产品 Bug。

查看只写入查询回执与回复，不调用模型或验证器、不重跑、不解除保护、不建立新任务队列。核对报告和当前源码后，另发真实新任务，使用已有 `/verify` 或 `/verify-repair` 入口；授权与修复次数限制沿用原规则。此命令不提供业务验收、独立 review 或发布授权。实际部署及客户端验收范围见 [验收记录](live-acceptance.md)。

这份说明给机器人使用者。你无需安装 Node、Codex 或飞书 CLI；需要应用部署者已把机器人发布给你，并把相关项目登记在运行电脑上。

工作在**部署者的本机环境**中执行。你登录飞书的身份用于准入和会话归属，不会把你自己的 GitHub、文件或飞书 OAuth 自动带到这台电脑。

命令统一使用英文小写；机器人说明和普通对话仍可用中文。旧中文 slash 命令不再执行，发送 `/help` 查看当前入口支持的命令。P1 网关的帮助只列出已实现的远程控制、恢复和排队操作；通用入口的 `/project`、`/chat`、`/new`、`/clear`、`/notify` 不因此扩展到 P1。

## 私聊与群聊

私聊机器人，直接发送文本。群聊里每个任务和控制命令都需要真实 `@机器人`；通过飞书成员选择器选择它，输入同名字符串不能替代 @mention。以下 `@工作分身` 是示意名称，替换为部署者的实际机器人。

```text
@工作分身 /status
@工作分身 关于上面的讨论，你有什么建议？
```

普通群消息、@所有人、@别的机器人和机器人发送的消息不触发任务。仅发一个 @、图片、语音或文件也不启动任务。

### 本人私聊的截图与文件（P1 网关）

在登记的本人私聊中，可在同一条消息里写清需求并粘贴截图。「换个话题」仍可新建事项，回复已结束的普通任务也可带截图。排队中或执行中的任务使用文字补充。审批等控制命令请单独发送。

网关只读取本条消息的附图，并作为原生图片输入传给 Codex。截图供判断页面和位置，操作范围以正文为准。图片必须全部读取成功才会提交模型轮次。若图片过大、格式不支持或读取失败，任务会在执行前结束；可缩小或重新粘贴图片后发新任务。

普通文件先发给 Bot。收到「已登记文件」后，用飞书「回复」选中文件消息，写清要做什么。如果文件本身引用了已结束的原任务或 Bot 最终答复，这轮会续接那个事项。要用同一个文件开新话题，直接再发一次文件，再回复文件写「换个话题，……」。仅登记文件不会开始模型任务。

网关按回复绑定的一条文件消息读取文件。单文件上限 10 MiB，下载预算 20 秒。普通文件允许不同扩展名，Codex 在本机用现有工具和权限按需读取；例如扫描 PDF 需要能用的 OCR。文件内容作为参考资料，任务授权来自回复正文。文件传输失败时任务在模型轮次前结束。任务收尾后清理本轮临时文件；执行结果不明时，等本机检查并解除保护后清理。要再次读取可以重新回复那条文件消息。

## 讨论与项目执行

默认是讨论模式，回答本次问题。已有前文 / 图片权限时可讨论群内提供的资料；读不到资料会说明。直接说明项目和需求即可，Codex 能确定时会进入已登记项目，不清楚时会问一个简短问题。也可用 `web：具体需求` 这样的已登记别名前缀明确发起新任务，跳过模型分类；这是可选的明确选择，不会沿用旧的待澄清请求。也可手动指定：

```text
@工作分身 /project web
@工作分身 阅读项目规则，检查登录接口为什么返回 401，先给出原因和修复方案。
```

`web` 必须是部署者登记的别名；`/project` 不接受聊天里传入的任意路径。发送 `/project` 可查看已登记别名。Codex 也会收到别名清单与当前选择，但清单不会自动选择项目或授予执行权限。选择后，后续普通消息会在此项目继续执行；用 `/chat` 返回讨论。自动选择只允许登记目录，并根据当前用户的请求判断；群内他人的话不会替你切换项目。

查询业务数据时说明产品或项目名称，让 Codex 核对项目规则、数据结构和真实数据源，再使用本机已授权的 CLI 或工具。项目不明时机器人会澄清；数据源不明时先补充项目上下文，不能因为某个分析工具可用就假定产品使用它。请说明统计时间范围、活跃定义和测试账号排除规则；项目未登记时需要部署者添加配置。

每位同事在每个聊天下有自己的会话和选择；你的 `/project` 不会替别人切换项目。不过所有人对同一目录的工作会串行等待。

## 给出可执行的工作需求

| 任务 | 可以这样说 | 依赖 |
| --- | --- | --- |
| 资料分析 | “根据这段资料，对比三个方案，注明已验证事实与推断。” | 所需资料已提供或本机 Codex 有搜索 / 读取工具 |
| 修 Bug | “订单提交偶发重复，定位原因、修复并运行相关检查。” | 已选项目、可重现信息、本机执行权限 |
| 做功能 | “给设置页增加通知开关，遵循项目规则，完成实现、验证并开 PR。” | 已选项目、需求和验收标准、GitHub 工具身份 |
| Review 本地变更 | “Review 当前分支相对主分支的完整 diff，重点检查回归与测试。” | 已选项目、明确比较基线 |
| Review PR | “Review 这个 PR 链接，指出能定位到代码的具体问题。” | PR 可访问，本机有相关工具 / 授权 |
| 飞书文档工作 | “读取这份有权限的需求文档，对照代码找遗漏。” | 本机另配飞书文档工具及资源授权 |

这些是 Codex 工作任务，不是 bridge 内置的固定功能按钮。只有配置了相关工具和身份、项目规则允许的动作才有执行条件。“开 PR”也不表示它可以自动合并或发布。部署者应说明自己委托同事提交的工作范围。

## 收到表情后意味着什么？

收到普通任务时，机器人尝试在原消息加 `OnIt` 表情，代表已收到；失败时退回一句确认。排队有说明；等待期间不会定时刷状态；需要审批或回答时才提示，最终答案单独回复。完成、失败或取消后清理自己的表情；网络故障可能延迟反馈和清理。

在已使用事项的本人私聊，任务回执标明「已接单」和事项名称，并提示在原任务消息的回复里查看最终结果。具备维护角色的本人可以复制回执上的 `/task` 命令查看这项任务的进度。带简短标题的「换个话题」请求优先使用正文分隔符前的标题，较长的通用标题会用省略号。

表情不是持续的在线指示灯，也不是已完成证明。`/status` 显示本机 Codex 进程是否连接、当前阶段、耗时和最近的 Codex 事件时间；进程连接不保证模型网络健康。bridge 不会因长等待自动重跑你的请求。

## 命令表

群里以下每条都要先 @机器人；私聊不需要。

| 命令 | 行为 |
| --- | --- |
| `/help` | 查看帮助 |
| `/project alias` | 选择已登记项目，进入执行模式 |
| `/chat` | 返回普通讨论 |
| `/status` | 查看正在做什么、排队数量和待确认请求；`/status details` 展示技术诊断 |
| `/new` | 当前会话没有运行 / 排队任务时新建会话，不删除旧历史 |
| `/steer 内容` | 给当前选中的运行任务补充要求；不是给下一个任务 |
| `/stop` | 请求停止自己的当前运行任务，排队任务保留 |
| `/notify @成员 内容` | 在当前群回复原提问并发送真实成员 @；通过成员选择器选人，一次最多 20 人，不创建或指派任务 |
| `/clear` | 取消自己的当前会话排队任务，运行任务不受影响 |
| `/approve 编号` | 指定审批人在指定聊天授权该请求 |
| `/reject 编号` | 指定审批人拒绝审批；原提交者可拒绝自己的提问 |
| `/answer 编号 内容` | 原提交者回答单个非敏感问题 |

`/steer` 和 `/answer` 的正文保留换行与代码缩进。普通消息在忙碌时会排队；想修正正在做的事情使用 `/steer`。想停止并清空后续工作，分别使用 `/stop` 和 `/clear`，并检查已经发生的文件 / 外部操作。

切换项目不会把已经排队的工作移到新目录，也不能用它控制别人的任务。原会话仍有工作时 `/new` 不会隐藏或丢弃审批。

## 审批在哪里处理？

命令 / 文件请求可以路由到部署者的指定私聊，提交者会收到等待说明；审批按用途、完整动作、工作区 / 请求和截止时间分区展示，避免重复长路径和原始需求。原提问元数据可用时显示已核实的提交者和原消息链接；姓名读取失败会说明，私聊审批不 @ 不在该聊天的提交者。同一私聊中，提交者也是指定审批人且卡片大小合适时，可点击“批准本次”或“拒绝”；需要在应用后台订阅卡片回调。其他审批范围或超长动作保留完整富文本预览。所有场景仍可回复 `/approve 编号` 或 `/reject 编号`。普通批准按钮只授权该次原生请求；可选“批准并记住”的用户级范围见下文。 手机端“批准本次 / 拒绝”各占半行；“批准并记住”在完整前缀及用户级范围下方独占整行。用途、截止时间和完整动作保持展开；请求编号、原任务链接和备用命令放在可展开的“备用命令与请求信息”中。收尾卡片先显示提交 / 过期结果，不再提供按钮，原动作与规则仍可展开查看。核对实际卡片消息、账号、聊天和任务；已处理 / 过期后会更新原卡片并移除按钮。网络故障可能延迟更新，旧按钮不因此获得授权。卡片初次投递尚未确认时拒绝点击，不能凭点击推断投递成功。显示按本机时区计算的实际截止时间；过期或已经处理的请求不会从待发送队列里再发出来，已在途的网络请求无法撤回。一般配置 300 秒超时，实际值由部署者设置；过期后拒绝，旧编号不能批准新任务。

单个非敏感问题仍由原提交者在原聊天用 `/answer 编号 内容` 回答，不必输入内部问题 ID；旧的匹配问题 ID 格式仍兼容。敏感问题、一个 RPC 中多个问题、扩展权限交互等暂不支持，会拒绝并提示到本机处理。不支持交互的详细原因留在 /status 和本机日志；最终答复说明影响和下一步，不额外插入技术提示。

审批仅在 Codex 的本机策略提出请求时出现；不能从“没有审批消息”推断没有做任何修改。

## 给它看群里图片或前文

先发送资料，再用一条文本 @机器人提问；也可引用要讨论的消息，包括 Bot 的原回复；引用会优先传给 Codex，即使同时开启自动前文。成员提及显示消息提供的姓名，身份信息不足时会明确标为未知，不会猜人。自动历史和图片下载默认关闭，需要部署者同意并配置。开启后只取触发前的有限上下文，机器人入群不会自动拿到全部历史、置顶文档和会议纪要。

消息写着 `[图片]` 不意味着图片已读到；bridge 会另行下载获准资源并作为真实图片输入，失败则明确未读。直接粘贴链接也不等于内容已展开。

## 等不到回复或任务中断

检查真实 @、应用可用范围和 `/status`。读不到前文时引用或粘贴内容；电脑休眠 / 断网需要部署者处理。进程退出或重启后，未确认完成的任务不自动重跑；重试之前检查已经发生的改动，避免重复执行。具体排查见 [常见问题](troubleshooting.md)。

## 用飞书回复补充或追问（P1 本人私聊）

在登记的本人私聊，对自己发送的原任务消息使用飞书的「回复」，直接写补充内容。比如回复「查 Solura 发版进度」说「也看下 CI」。发送独立普通消息可交办另一件工作。

| 原任务状态 | 回复的去向 |
| --- | --- |
| 等待派活 | 加入原任务的输入，随原任务一起执行 |
| 正在执行 | 补进原任务当前的 Codex turn，收到原生接收回执后表示已送入 |
| 已确认收尾 | 沿用经核对的原会话，排入一条关联追问 |

原任务在送达前刚结束时，确认这句补充未生效后才会排为追问。接收情况不明时保留核查，等待回执。验证、修复和权限续接使用原有的专用入口。引用回复的范围是登记私聊里你自己发起的原任务消息。

## 更自然地补充、停止和通知

同一聊天下只有一个你正在运行的任务时，可以说“补充：只看最近一周”“只看最近一周”“先别修改”，它们会补充到当前任务；新任务仍排队。存在多个任务或引用无法关联时，会请你引用自己的原提问，不猜任务。执行阶段未引用任务、也未明确说“补充”或给出禁止修改等限制时，明确提到另一个已登记项目的读取需求按新任务处理。引用绑定、明确补充和分类中的限制会传给当前任务，不根据内部讨论工作区猜项目。也可引用 Bot 对该任务的回复；关联由 SQLite 记录并按租户、用户和聊天校验，引用其他人的任务不会替你控制它。

“先停一下”“停一下”“别继续了”停止绑定的当前任务，并清理该会话后面的排队请求；“停止当前任务”“取消当前任务”及 `/stop` 保留后续队列。已有操作不会自动撤回。任务尚未执行时的文字补充会加入首次输入；开始请求尚未确认时不会假装补充已接收，可以先停止再重新说明。停止未确认时明确要求核对本机结果，后续排队任务取消，不自动重跑。

群里可发送 `@Bot /notify @成员 通知内容`，或者 `@Bot 请通知 @成员 通知内容`。成员必须是本条消息通过飞书选择器真实 @ 的目标，不根据显示名猜账号，不通知所有人，不跨聊天发送，私聊不通知第三人。发送真实 @ 不证明对方已读；分工建议、成员通知、创建任务和实际指派是不同动作。重复事件不会重复发送新的通知；投递失败按固定 UUID 重试，仍受平台去重窗口限制。

结果直接回复实际发起任务的消息，项目与内部任务编号不再默认附在答案末尾。引用消息被撤回或删除时，收到明确错误后才退回原聊天发送；网络结果不确定时继续重试原回复方式，不换地方重复发。消息过长及已获准用户的不支持格式会给出处理提示，而不是静默忽略。普通等待仍不定时刷消息，重启后的恢复说明按提交者/聊天汇总。

同一项目的执行结果未确认时，此前已进入分类流程的请求也会在交接时停止；先核对本机结果，再发起新请求，不自动重跑。简化问题回答只移除编号后的一个分隔符，保留内容的换行和缩进。

部署者可在本机查看 [默认队列和 P1 Autoloop 的分段耗时](operation.md#metrics-after-live-setup)。`/answer` 缺少内容时保留问题等待状态，请补上答案再发送。

## 通用工作区

部署者启用 `projectRouting: "workspace"` 后，直接说明需求即可。需要操作代码时，在任务中说明仓库或目录，例如“只读检查指定仓库的发布流程”；资料整理和其他工具任务也可直接交办。目标有歧义时，Codex 会先澄清。文件、命令与外部工具访问沿用部署主机的权限和原生审批。

`/status` 显示“通用工作区”。`/project` 会提示在当前需求中说明目标，`/chat` 返回通用工作区，`/new` 创建新的工作区会话。P1 网关的可用命令以其交接组件说明为准。

## P2：检查后恢复（P1 网关）

`/recover` 仅供已登记任务本人在登记私聊使用，本人还须是 `approvalUsers` 中的审批人，且私聊符合 `approvalChat`；这些配置沿用现有字段。群聊、代其他人审批的管理员和普通入口不提供此维护能力。

出现结果未确认后，发送 `/recover` 查看对应恢复编号和封存证据是否可用。先确认原命令及其后代进程均已停止，并核对文件和外部服务的实际结果，再发送：

```text
/recover <完整恢复编号> <检查依据，最长 1800 字符>
```

发送此命令表示你已完成进程和副作用检查。系统只验证原生子进程的封存退出与日志完整性；你的检查依据属于人工确认，不是系统已自动验证全部副作用。缺少封存证据、原执行器仍可连接或还有已接收的未执行任务时，需要本机维护。

成功只解除指定任务的保护，原任务仍为结果未确认；不会重跑原任务、重新放行已阻断的请求、取消维护暂停或关闭 Hub 业务卡片。后续工作请新发消息。确认后丢失回执可再查 `/recover`；系统会从已提交的恢复记录补投回执。提交前连接中断的维护指令不会自动重放，需要一条新的本人消息。

部署与真实验收状态以 [验收记录](live-acceptance.md) 为准。

### 只读故障报告

诊断版本的 `/recover` 会展示核查时间、执行器控制连接、封存日志及结果、登记进程和后代的当前观测、队列/投递计数，以及绑定的 Hub 调度轮次。每项分别说明已核实、仍运行或无法核实。Hub 轮次结束只描述调度状态，任务仍可能保持结果未确认。

进程范围限于运行时已采样登记的 PID 与启动身份。未登记、采样失败、身份变化或可见性不足的进程无法据此判定安全；旧任务缺少记录时会明确显示无法核实。报告不展示原始命令、环境或私有路径，也不清理进程、修改队列或解除保护。报告是带时间的快照，确认恢复时会重新校验，实际文件和外部服务的副作用仍需人工核对。

该能力的实际部署和验收状态见 [验收记录](live-acceptance.md)，具体范围见 [诊断设计](../openspec/changes/archive/2026-11-16-add-readonly-incident-diagnostics/design.md)。

### P1 排队查看与撤回

在已登记本人的私聊中，本人同时具有审批角色时，可发送 `/queue` 查看尚未取得执行授权的请求。列表只显示请求编号、收到时间和排队/阻断状态，不展示任务正文；每次显示数量有上限，见 [实现](../src/handoff/queue.ts)。

发送 `/withdraw 完整请求编号`，或引用自己原来发送的任务消息并发送 `/withdraw`，可撤回一个尚未开始的请求。若编号与引用冲突、目标不属于自己，或 Worker 已经取得执行授权，操作会被拒绝。运行中的任务继续使用 `/stop`。撤回记录会保留，重启或原消息重复投递不会再次执行；需要处理时请发送新的任务。

撤回不会终止进程、解除未确认保护、恢复维护暂停或取消 Hub 轮次/卡片；Hub 中该轮仍可能结束，原请求则不会再启动模型。尚未取得授权的请求撤回后不再计入待执行和已阻断数量。具体部署范围和真实验收以 [验收记录](live-acceptance.md) 为准。


## 回复排版

普通回答、系统回执和控制查询都使用飞书原生富文本。普通回答在原有 Codex 生成中采用结论在前、短段落、独立小标题和逐项列表；简短回复保持简短。发送层统一压缩标题层级、保留分区空行，并原样保留围栏代码内容。

验证、状态、队列、恢复诊断和帮助使用程序生成的固定分区。验证先显示观测结论与声明范围，代码/UI/发布分别列出；执行保护和历史适用性单独说明。完整任务编号、报告目录与文件名集中在末尾可复制代码块，报告仍是本机引用。队列提供包含完整编号的撤回命令；审批继续使用已有按钮卡片或英文命令。

排版不增加第二次模型调用。普通回答的格式要求属于原有生成指令，仍会占用正常提示词用量；系统模板与富文本转换不调用模型。排版不改变授权、观测含义、任务编号或封存证据，也不会重写已投递的旧消息。实际客户端布局验收见 [真实验收记录](live-acceptance.md)。

官方富文本能力参考：[发送消息内容结构](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json?lang=zh-CN)。

## 可选原生权限管理（P1 本人私聊）

启用后，常规权限交给 Codex sandbox、原生规则和 Auto-review。只有 Codex 提出可保存的有效命令建议时，才显示“批准并记住”；它保存本机 Codex 用户级前缀，影响其他共用配置的会话。`/approve-save 编号` 是对应文字入口。普通批准和拒绝不写长期规则。

- `/rules` 查看 Bot 授权记录与当前用户规则文件；`/rules revoke 规则编号` 添加重新审查覆盖，`/rules allow 规则编号` 仅移除该覆盖。
- `/reviews` 查看最近非通过审查；`/review 完整编号` 查看动作与原因。
- 符合条件的拒绝卡片可点击“授权此动作，发起一次重试”，或发送 `/review-retry 完整编号`。这会登记一个新的受审查任务；不会重跑旧任务、直接绕过审查或保存长期规则。超时、中止、保护未解除、证据不符或会话已推进时不提供该授权。

查看结果用 `/tasks` 与 `/task`。原生结束、规则保存、项目验证和发布授权分别判断。完整作用范围、撤销时效和原生上下文保留限制见 [权限说明](native-permissions.md)。部署与真实交互验收进度以 [任务清单](../openspec/changes/enable-owner-native-permissions/tasks.md) 为准。

## 浏览器站点权限受阻（P1）

浏览器的站点允许/拒绝独立于 Codex 命令规则和 Auto-review。支持的工具返回明确结构化拒绝后，任务详情与一次系统通知会列出最近受阻站点及本机处理入口；原生回合收尾不证明联系、提交或其他业务目标已经交付。历史观测不保证当前仍被阻止。

`允许浏览器工具访问` 等明确短语只返回处理指引，不会新增模型任务或修改设置。本机实际处理并核对原任务副作用后，可在纯文本消息中发送 `/browser-retry 完整编号 local-change-confirmed`。这会在满足证据、会话与保护条件时登记一个关联的新普通请求；重复操作只返回已有请求。浏览器仍会真实校验权限，拒绝后不自动循环。验证/修复任务从其专用入口重新明确计划。旧任务可能没有结构化观测，不能靠查看补成已授权。详见 [流程与限制](browser-access.md)。

## 按事项切换 Codex 会话

在本人私聊用 `/matter-new 事项名称` 新建并切换，或用 `/matters` 从卡片切换。回复 Bot 普通最终答案或事项卡片，也可以用精确事项名前缀或已绑定的 PR 定位原会话。短追问可能涉及两个事项，或引用答案和正文指向不同事项时，会先显示选择卡。接收回执会显示实际归属。见 [飞书事项](owner-matters.md)。
