# 飞书事项与会话

在登记的本人私聊中，使用 `/matter-new 事项名称` 新建事项并切换。直接发送任务就会使用选中的事项。用 `/matters` 查看事项并点击切换，列表也可以切回默认对话。命名事项各有一份会话历史，第一次执行时才由 Codex 创建 thread。

- 回复原任务会按照原来的排队、执行中补充或收尾后追问规则处理。回复单个事项卡片会使用该事项，即使当前选的是另一件事。
- 发「事项名称：任务内容」可以按精确名称直达。选中一个命名事项后，用 `/matter-bind GitHub PR 链接` 登记它的关联对象。以后包含该链接的任务会直接使用绑定的事项。
- 当输入指向多个可能的事项时，机器人先保存原消息并给出候选。点击后才会排队，只能处理一次。选择后，新的普通消息可以继续沿用该事项。候选过多时，可以引用相应事项卡片或明确填写事项名称再发。
- 事项归属只决定普通任务的会话历史。审批、恢复、验证等专项命令继续使用各自的来源和授权。选择事项不会执行命令或扩大当前工作目录的权限。

AutoLoop 使用每次请求的 ID 派工，Bridge 决定续接哪个 thread。使用同一目录的任务由原有执行保护串行处理。
