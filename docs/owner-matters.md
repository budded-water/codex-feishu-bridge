# 飞书事项与会话

在登记的本人私聊中，使用 `/matter-new 事项名称` 新建事项并切换。直接发送任务就会使用选中的事项。用 `/matters` 查看事项并点击切换，列表也可以切回默认对话。命名事项各有一份会话历史，第一次执行时才由 Codex 创建 thread。

- 回复原任务会按照原来的排队、执行中补充或收尾后追问规则处理。也可以直接回复 Bot 已确认送达的普通最终答案，在原事项中开始一轮追问。回复单个事项卡片会使用该事项，即使当前选的是另一件事。早期未登记为续接入口的消息可以用原任务或事项卡片续接。
- 要补充某一轮正在执行的任务，可以回复那条原任务。无引用也无明确事项地址时，现有自然补充仍作用于正在执行的任务。选中了命名事项且没有任务正在执行时，「只查询」等只读请求会交给该事项。
- 发「事项名称：任务内容」可以按精确名称直达。名称与项目别名相同时，该前缀用于选择事项，执行范围仍由既有授权决定。若卡片和前缀指向不同事项，机器人会请你选择。选中一个命名事项后，用 `/matter-bind GitHub PR 链接` 登记它的关联对象。以后纯文本消息中包含该链接的任务会直接使用绑定的事项。
- 当输入指向多个可能的事项，或引用尚无法确认时，机器人先保存原消息并给出候选。点击后才会排队，只能处理一次。选择后，新的普通消息可以继续沿用该事项。候选过多时，可以引用相应事项卡片或明确填写事项名称再发。需要重发的旧消息会保留原决定。
- 从有任务记录的事项切走后，新事项尚未收到任务时，单独发送「刚才那个？」或「继续上一步」会先让你在前后两个事项里选。已经明确交办新事项，或点选确认归属后，可继续直接聊天。普通任务的接收回执会标出实际进入的事项，选中默认对话时也会显示归属。
- 事项归属决定普通任务的会话历史。引用内容发送 `/steer` 时，请引用运行中任务的原消息。审批、恢复、验证等专项命令使用各自的来源和授权。

AutoLoop 使用每次请求的 ID 派工，Bridge 决定续接哪个 thread。使用同一目录的任务由原有执行保护串行处理。
